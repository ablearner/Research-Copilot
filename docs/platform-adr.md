# 平台部署 ADR

## ADR-001：本机多进程运行，数据库为业务状态真相

状态：采用。API、Worker、Scheduler 作为独立进程；本机 supervisor 管理生命周期。MySQL 保存任务/attempt/lease/outbox/业务记录，RabbitMQ 仅传任务引用，Redis 用于限流。API 不启动匿名旧路由。代价是依赖进程管理器、日志收集和显式迁移；生产不能直接复用开发口令。

## ADR-002：本地停机一致性备份，队列由 outbox 重建

状态：采用于本地 profile。停止应用写入与数据库/对象容器，备份 MySQL、对象文件和 Worker SQLite 工件；不宣称跨存储在线原子快照。恢复到空卷，验证清单，显式迁移，重放 outbox，租约恢复未完成任务。RabbitMQ 物理卷不恢复，避免节点名绑定；因此消费者必须支持重复投递。代价是有停机窗口、备份含敏感内容，RPO/RTO 需实测，外部向量库不在默认覆盖范围。

## ADR-003：单机 Worker 与离线演示不代表生产容量或研究质量

状态：采用。SQLite 派生记忆与本机文件要求保持单机约束；模型/embedding/vector provider 的真实部署配置由 `.env` 提供。`--offline` 只验证流程接通，内存索引可从已提交解析工件重建，不得用于宣称 LLM 或 RAG 效果。扩到多主机前需替换或集中管理记忆写入，并验证任务并发、隔离和恢复。
