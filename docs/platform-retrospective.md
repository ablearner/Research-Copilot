# 后端工程复盘

以下三篇围绕当前实现的故障窗口和设计取舍。源码与测试名称可供复核；测试是否通过、硬件与性能数据以[验证记录](platform-validation.md)为准，不把代码存在等同于生产验证。

## 一、事务 Outbox 与幂等：接受任务之后不能悄悄丢失

### 问题与失败窗口

原有进程内后台任务不能独立于 API 生命周期存活。即使改成队列，先插数据库再发消息仍有“提交后进程崩溃”的空窗；先发消息再提交则可能让 Worker 看见不存在的任务。把网络投递放进事务，也无法让 MySQL 和 RabbitMQ 原子提交，还会延长锁持有时间。

当前提交事务把任务、幂等记录与 Outbox 一起提交，研究任务同时保存用户消息。API 接受意味着派发意图已持久化，而非模型已开始执行。Scheduler 读取 Outbox，持久化消息发送得到 publisher confirm 后，才记录已投递。

### 为什么仍然需要三种标识

| 标识 | 约束的竞态 | 不保证什么 |
| --- | --- | --- |
| 请求幂等键 | 同一工作区、用户、操作、键的重复提交返回同一逻辑任务；内容不同产生冲突 | 不防止用户用不同键提交语义相似问题 |
| `generation` | 旧派发消息不能抢跑当前退避等待；领取必须匹配当前代次和到期时间 | 不表示执行已经成功 |
| `execution_epoch` | 新 attempt 启动后，旧 Worker 不能提交事件、阶段或终态 | 不撤销已经发给外部模型的请求 |

确认发送后、标记 Outbox 前崩溃会重投，这是允许的故障行为。消费者在数据库事务中领取，持久化 attempt/lease 后短确认；重复消息无法重复领取已运行任务。Worker 在领取前先获取本地槽位，避免确认后无限堆积执行。用户级运行/排队约束和本地槽位分别保护公平性与进程资源。

### 宕机如何恢复

心跳续租使用数据库时间；恢复器发现过期 attempt，标记 expired 并有限重试。旧执行者即使恢复，也必须通过 epoch、状态和有效租约检查。取消先持久化；完成与取消共享受控状态变更，已成功任务不能被迟到取消覆盖。PDF 解析进入有界子进程，使 CPU 工作不会直接卡住事件循环心跳。

代码入口是 `services/task_execution/__init__.py`、`adapters/queue/rabbitmq.py`、`services/platform/runner.py`。故障用例包括：

- `test_confirm_mark_gap_retains_outbox_and_permits_duplicate_delivery`：确认和标记之间的重复投递窗口。
- `test_killed_claiming_process_recovers_without_duplicate_commit`：真实领取子进程终止后的恢复和旧 epoch 拒绝。
- `test_poison_payloads_are_rejected_without_calling_handler`：毒消息拒绝，避免无限污染执行链路。
- `test_conversation_serialization_stages_and_expiry_bound`：同会话串行与阶段/次数约束。

### 取舍

这里实现的是可重复投递与业务受控发布，不是跨系统恰好一次。研究任务可能重新调用模型，结果和费用不一定相同。恢复以业务阶段为单位，不能承诺恢复 LangGraph 中途推理栈。首期接受单机 Worker 和有界重试，避免为演示引入自研队列、分布式锁服务或微服务拆分。

## 二、文档跨存储一致性：让未完成产物保持不可见

### 问题

PDF 位于对象存储，文档状态在 MySQL，检索需要向量和图。把一个 `uploaded=true` 当成可问答会导致解析失败却仍出现在研究范围里；让两个重试覆盖同一产物路径，会让旧 Worker 改坏新结果；删除数据库记录却不限制检索，会继续返回旧证据。

### 采用“先产物，后发布”

上传初始化创建短期上传会话和受限 POST 授权；完成接口重新读取对象，检查大小、PDF 内容和哈希。工作区内上传去重通过受锁保护的查询收敛，不能向其他工作区暴露命中。验证后的内容写到业务对象，原上传授权对象不是长期可信引用。

每个处理版本记录文件哈希、parser 与 embedding 配置标识。下载、解析、索引有阶段指纹，重试可以复用已提交成功产物；解析 JSON 对象键包含文档版本、任务和 epoch，避免旧 attempt 覆盖新产物。索引成功后，在事务内复核权限、任务租约与文档状态，再发布活动版本。

当前索引按 attempt 创建并清理，后续研究从已发布解析结果重建授权索引。因此“索引完成”是处理成功状态，不表示一个共享向量集合永久存在。这一取舍增加了研究准备成本，但使早期隔离边界更容易核查。未来共享索引需要单独设计版本过滤、发布与回收契约。

### 删除分成可见性与物理清理

删除事务先标记文档 tombstone 并写清理 Outbox，新的文件读取和研究权限判断立刻拒绝。检索前后再次校验，防止查询期间权限变化或文档被删除。后台再删除对象、相关索引和记忆；不能让清理耗时决定逻辑删除何时生效。

这里的“立即不可访问”针对后续经服务端授权的读取，不会追回已经下载的字节或发给模型的上下文。私有文件走鉴权下载代理，没有承诺已发出的任意外部链接可瞬间撤销。

### 孤立产物与验证

跨存储失败允许留下不可见孤立对象，优于发布一个不存在或不完整的结果。`ObjectReconciler` 先扫描满足保留时长的对象，再核对 MySQL 文件、解析、任务、阶段和上传引用；默认 dry-run，明确 apply 才删除。它是运维对账工具，不是覆盖所有历史本地文件和异常退出 Milvus 集合的自动垃圾回收器。

可复核 `test_signed_upload_verifies_bytes_and_retries_completion`、`test_actual_pdf_import_and_supervisor_answer`、`test_partial_import_can_retry_with_durable_success_stages` 及 `tests/unit/platform/test_reconciliation.py`。核心实现位于 `uploads.py`、`business.py`、`runner.py`、`reconciliation.py`。

备份必须同时考虑 MySQL、对象存储和 Worker 记忆目录。即使行数和对象哈希一致，也不能据此宣布所有多模态能力恢复：解析 JSON 中的本地图像路径、索引重新构建仍需另验。对账、备份恢复和质量评测解决不同问题。

## 三、Agent 多用户隔离：不能只在 API 加一个 user_id

### 威胁从哪里进入

API 查询加工作区条件，只能保护业务表。Agent 还可能经过默认 `local-user`、共享 MemoryManager、全局向量集合、图遍历、个人 Zotero 和本地文件路径获取数据。模型输出的 `document_ids` 也不能被当作授权依据。

当前 Worker 从持久任务恢复用户与工作区，构建冻结的 `ExecutionContext`，把授权文档元组和超时传入桥接层。模型不能构造 Context 来替换身份。数据库身份检查覆盖活跃用户、成员角色、项目和当前文档版本，并在执行与结果发布时复核。

### 隔离发生在工具以下

`AgentBridge.scoped_settings` 将临时目录、记忆路径与向量集合限定到 attempt；图使用新建 memory provider。研究只把当前授权活动文档载入该 runtime。`ScopedRetriever` 在底层工具共享的检索入口检查：请求文档必须为授权子集，返回命中和证据也必须属于该集合，检索前后都复核实时权限。

图隔离主要依赖每次执行的新图仅接收授权文档，不能将其描述为已经验证了任意共享图数据库的多跳来源过滤。Milvus 集合名按工作区与 attempt 根目录派生并在结束时清理；本地 memory provider 用例不等于实际 Milvus 多租户压测。

在线桥接关闭服务器个人 Zotero、MCP 注册表和本地代码执行，公共学术检索保留。自动 PDF 下载只支持通过校验的 arXiv 标识。首期未开放工作区自带第三方工具凭据，因而没有宣称已完成用户工具凭据托管。

### 记忆也要有提交点

每次 attempt 的 SQLite 从已提交快照复制，运行中写入只影响私有副本。作用域哈希包含用户、工作区、项目、会话及文档版本；变更文档范围不会复用旧范围的记忆。最终业务结果发布后才提交记忆快照，提交前再次核对任务 epoch/终态、权限和文档有效版本。发布水位避免较旧 pending 快照覆盖较新的已提交快照。

业务成功而记忆发布失败时，保留待提交记录，在 Worker 启动和同会话下一次研究前重试。该故障不回滚已经成功的报告。同会话的进程内锁覆盖研究及记忆发布，数据库领取也阻止同会话同时运行。

这仍依赖单 Worker 部署。把多个 Worker 指向共享 SQLite 目录，不会自动获得跨进程提交顺序；扩容需要先设计记忆服务或共享事务后端，并验证并发写入、恢复和删除传播。

### 回归证据与限制

`tests/unit/platform/test_scope.py` 覆盖检索后复核、不同 attempt 独立配置和底层 provider 返回越权证据时拒绝。`test_memory_commit.py` 覆盖成功发布门槛、版本作用域与复用。浏览器用例验证 A 的私有 PDF 不能被 B 获取；研究集成测试验证真实解析和 Supervisor 的业务衔接。

这些证据分别覆盖权限契约、用户流程和 runtime 接入。仍需真实模型质量、真实向量 provider、复杂图证据和少量真实用户试用的专项验收。完整保留 Agent 能力的判断应同时看既有 RAG 评测，不能仅用“HTTP 返回 200”替代研究正确性。
